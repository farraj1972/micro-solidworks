# Scripting and Extensibility Reference — DRAFT / DEFERRED

Source: [specification v0.1 §7](sources/MICRO_CADCAM_PRODUCT_SPEC_V0_1.md), resolved against [P0-D06](../PERSONAL_SOLIDWORKS_P0_DECISIONS.md). The source calls scripting P0; **that is its Original Priority, not authorization for v1.2**. No scripting runtime, public extension host, Python/Lua choice or third-party dependency is implemented by SPEC-01.

Target contracts for a future decision: a versioned project-owned command API shared by UI and scripts; `canExecute`, `preview`, `execute`, `validate`, `cancel` and transactional commit; declarative feature parameter/dependency/output schemas; deterministic rebuild; stable persistence/migration; Undo/Redo; diagnostics and bounded resource use. Scripts must not mutate [`FeatureModel`](../../src/features/FeatureModel.h) internals outside approved transactions. File/network/process access needs explicit capabilities and consent; untrusted scripts should be disabled by default until a threat model is approved.

Current [`EditorContext`](../../src/interaction/EditorContext.h) exposes internal editor commands, and [`FeatureModel`](../../src/features/FeatureModel.h) has controlled native operations. Neither is a public, versioned script API. A future language-independent adapter is a proposal, not an abstraction to add speculatively. Python and Lua remain **OPEN alternatives**. A later Decision Gate must compare licensing, embedding/Windows packaging, security isolation, deterministic execution, versioned extension format and migration. Scripted features or CAM job automation are downstream of that gate and their respective domain contracts. Normal CAD work remains GUI/mouse-first; scripts extend rather than replace it.
