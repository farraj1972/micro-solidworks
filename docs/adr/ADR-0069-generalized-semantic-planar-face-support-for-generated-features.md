# ADR-0069 — Generalized Semantic Planar-Face Support for Generated Features

Status: ACCEPTED

## Context

D18 supports semantic StartCap/EndCap references only for a single-body Extrude.
After a successful Cut Extrude, visible planar faces are generated by the Cut
result and their FaceIds and body indices remain rebuild-local under D15. C4
needs the block → pocket → Sketch-on-pocket-floor workflow without introducing
general persistent topological naming.

## Decision

Generalize semantic Sketch support to an authoritative descriptor containing a
source FeatureId and a closed semantic role:

```text
ExtrudeStartCap
ExtrudeEndCap
CutInheritedStartCap
CutInheritedEndCap
CutPocketFloor
```

The source Feature rebuild produces derived face-provenance metadata mapping
current rebuild-local faces to these roles. Raw FaceId, body index, tessellation
index and geometric nearest-match data are never persisted. Command-time
selection converts a derived face target to a semantic descriptor and discards
the topology target.

A role is valid only when it resolves to exactly one planar Face in a
single-body result. Cut inherited-cap roles are supported only when the role has
one connected Face component. Ambiguous or absent inherited caps are unsupported.
`CutPocketFloor` additionally requires one cutting material region, one resulting
body and exactly one generated planar pocket floor. Multiple-region floors,
split/multi-body results and side faces are unsupported in C4.

Rebuild resolves the source first, inspects derived provenance, requires exactly
one matching planar face and derives a deterministic right-handed SketchPlane.
A missing face makes the Sketch FAILED and blocks dependants. Multiple matches
make it FAILED with `The sketch support face is ambiguous after rebuild.` There
is no nearest-face search or automatic reattachment. Changing Blind Cut depth
moves `CutPocketFloor` and the supported Sketch while preserving local geometry;
if the floor disappears, rebuild fails explicitly.

Persistence remains `.microsw` format version 2. Existing `StartCap` and
`EndCap` tokens retain their meaning and remain readable. The v2 reader accepts
new generated-role tokens and rejects unknown roles. This additive active-C4
extension does not require format version 3. Derived provenance is not persisted.

## Rationale

Feature-generation roles provide associative identity for a narrow, useful CAD
workflow without claiming persistent topology naming. Exact-one resolution and
single-region/single-body restrictions avoid unstable region or component
indices while retaining deterministic failure.

## Consequences

- Semantic support becomes a role variant rather than an Extrude-only cap enum.
- Cut reconstruction emits derived provenance for inherited caps and the
  eligible pocket floor.
- Selection and properties expose human-readable generated roles.
- Existing v2 files remain compatible.
- Deleting a source follows ADR-0068 and removes supported dependants.

## Alternatives Considered

Persisting FaceId/body index violates D15. Geometric snapshots lose
associativity. Nearest-face reattachment can silently select the wrong face.
Stable region indices require a separate region-identity design. General
topological naming is disproportionate to C4.

## Deferred / Non-goals

Multiple cutting-region floors, multi-body face identity, pocket side faces,
cylindrical support, Boolean-generated faces, arbitrary planar faces, manual
reattachment and general persistent topological naming.
